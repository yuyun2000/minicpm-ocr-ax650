# AX8860 前瞻：这台 1.3B OCR 在下一代芯片上大概能跑多快

> 2026-11-11｜基于 AX8850 实测 + AX8860 公开规格做的**带宽/算力建模估算**，不是实测。
> AX8860 上市后，用本仓库脚本重编、上板即可验证（见文末「等 AX8860 来了怎么做」）。

## 0. 命名约定（先统一）

- **产品/部署对外统一称 AX8850 系列**：现有两块板（192.168.10.144 / 192.168.10.105）都是 AX8850 系列，
  分别对应 AX650N / AX650C 板型；`/proc/ax_proc/chip_type` 里仍会显示 `AX650*`。
- **编译目标保留 `AX650` 字样**：Pulsar2 的 `--chip AX650` / `target_hardware: AX650` 是工具链目标名，
  同包在 AX8850 系列板上兼容运行（本仓库产物即如此）。
- 下文若提到「实测」，都是在 AX8850 系列板上跑出来的；提到「AX8860」都是公开资料 + 估算。

## 2. 当前这个模型在 AX8850 上的瓶颈在哪

实测（AX8850 系列板，U16 vision + INT8 LLM）：

| 指标 | 实测 |
|---|---|
| decode | **10.5–11.6 tok/s** |
| 单块 448×448 表格 OCR（233 token） | **21.7–23.2 s** |
| TTFT（视觉 + prefill） | **2.1 s**（视觉 0.6 s + 文本 prefill ≈1.5 s / 277 token） |
| 版面模式 PPT 页（6 区域） | **19.5–21.2 s** |
| 整页 page 模式（9 片） | **147 s** |

**decode 是内存带宽瓶颈**：这个 1.3B VLM 的文本 LLM 是 752 M 参数，每生成 1 token 要读一遍
LLM 层权重（24 层 axmodel ≈ 626 MB）+ post/lm_head（≈970 MB），合计约 **1.6 GB/token**。

```
带宽占用 = 11.6 tok/s × 1.6 GB/token ≈ 19 GB/s
AX8850 峰值 34 GB/s  →  有效利用率约 55%（对端侧运行时是正常水平）
```

也就是说：**decode 速度 ≈ 带宽 × 利用率 ÷ 每 token 权重字节数**，想快就得涨带宽或减权重字节。

## 3. 估算方法

两条线分别估：

1. **decode（带宽 bound）**：按带宽倍数线性外推，利用率沿用 55%；
2. **prefill / vision（算力 + 带宽混合）**：AX8860 NPU 算力 10.7×、带宽 4×；
   小 batch 下实际更接近带宽受限，取 **3.5–4×** 保守估计；
3. 权重仍是 **INT8**（2.6 GB 包，与现在同构），除非明确标注「INT4/FP4 权重量化后」——
   AX8860 原生支持 INT4/FP4，理论可把每 token 权重字节减半，但对这个模型需要重新验证精度。

## 4. 估算结果（同一套 axmodel 结构，重编到 AX8860）

### 4.1 AX8860（136 GB/s，64 GB LPDDR5X）

| 指标 | AX8850 实测 | AX8860 估算 | 提升 |
|---|---|---|---|
| decode | 11.6 tok/s | **≈ 45 tok/s**（40–50） | ≈4× |
| 单块表格 OCR（233 token） | 22 s | **≈ 5.5 s**（5–6 s） | ≈4× |
| TTFT | 2.1 s | **≈ 0.5 s** | ≈4× |
| 版面模式 6 区域 | 20 s | **≈ 4–5 s** | ≈4× |
| 整页 9 片 | 147 s | **≈ 35–40 s** | ≈4× |
| vision 448 编码 | 615 ms | **≈ 60–150 ms** | 4–10× |
| 版面检测 | 213 ms | **≈ 30–60 ms** | 4–7× |
| 流式首字 | 2.1 s | **≈ 0.4–0.6 s** | ≈4× |

| 指标 | 估算 | 说明 |
|---|---|---|
| decode | **≈ 90 tok/s**（80–100） | 带宽 8× AX8850 |
| 单块表格 OCR | **≈ 2.5–3 s** | |
| 整页 9 片 | **≈ 18–22 s** | |
| TTFT | **≈ 0.4 s** | |

### 4.3 如果再做 INT4/FP4 权重量化（AX8860 原生支持）

每 token 权重字节从 1.6 GB 降到 ≈0.85 GB → decode 再翻倍：

| 配置 | decode 估算 |
|---|---|
| AX8860 + INT8 权重 | ≈ 45 tok/s |
| **AX8860 + INT4/FP4 权重** | **≈ 85–95 tok/s** |
| **AX8860P + INT4/FP4 权重** | **≈ 160–190 tok/s**（接近 27B 模型 FP4 的公开宣称量级） |

> 注意：INT4 需要重新做量化校准 + 精度验证；本仓库的 U16 vision 精度经验说明「不是所有层都能压」。

## 5. 还有一个更重要的收益：能跑更大的模型

AX8850 的 32 GB / 34 GB/s 决定了它只能跑 1.3B 这种小模型；AX8860 的
**64–128 GB LPDDR5X + 136–273 GB/s** 意味着：

| 模型（INT8 权重） | AX8850 | AX8860（64 GB） | AX8860P（128 GB） |
|---|---|---|---|
| 当前 1.3B OCR | ✅ 23 s/块 | ✅ ≈5.5 s/块 | ✅ ≈3 s/块 |
| 3B | 很紧（3.9 GB） | ✅ | ✅ |
| 7B | ❌ | ✅（~8 GB） | ✅ |
| 27B | ❌ | ✅（~27 GB） | ✅ |
| 27B FP4 | ❌ | ✅（~14 GB） | ✅（≈20 tok/s 公开口径） |

对 OCR 场景的实际意义：可以把「版面检测 + 更大的识别模型 + 高分辨率切片」放进同一个板子，
不必再靠应用侧极致的切片/降采样来省资源。

## 6. 等 AX8860 来了怎么做（给未来的自己/接手的人）

1. **工具链**：AX8860 换了一代 NPU（INT4/FP4/BF16、支持 vLLM/SGLang），现有 Pulsar2 8.0 产物不能直接用；
   需要拿到对应版本的 Pulsar2 / axmodel 编译器（或官方 vLLM 插件）。
2. **重编**：本仓库 `scripts/` 里的导出脚本（vision ONNX、LLM `llm_build2` 参数）、校准集生成、
   组装脚本基本可复用，只改 `--chip AX8860`（或新工具链的等价参数）。
3. **优先试**：INT8 版先跑通对拍（cosine ≥0.99），再试 INT4/FP4 权重看精度/速度权衡。
4. **实测并回填**：把真实 decode/TTFT/整页耗时写进 `docs/performance.md` 与本文的「估算 vs 实测」对照表。
5. **版面+表格**：AX8860 的算力足以把 `layout` 模式做成默认路径（现在是可选），甚至加表格结构模型。

## 7. 结论（一句话）

- 当前 AX8850：**22 s/块、11.6 tok/s，能用但偏慢**，瓶颈是 34 GB/s 的 LPDDR4x 带宽；
- AX8860（136 GB/s）：同模型预计 **≈4× 提速，单块 5–6 s、TTFT 0.5 s**；
- AX8860P（273 GB/s）：**≈8×，单块 3 s 内、TTFT 0.4 s**；
- 若再用原生 INT4/FP4：decode 可到 **85–190 tok/s** 量级（需重新量化验证）。
- 以上均为建模估算，**最终以 AX8860 上板实测为准**——到时候回到这个仓库，按第 6 节跑一遍即可。
